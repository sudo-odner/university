# Лабораторная работа № 4 — экспертные системы на Прологе

**Дисциплина:** Системы искусственного интеллекта. **Вариант 8:** компьютерные вирусы.

## Цель и задача

Изучить логический и продукционный способы представления знаний в экспертных системах. Разработать две системы для учебной классификации 12 типов вредоносных программ по 10 признакам с ответами «да» и «нет». Вариант называется «Компьютерные вирусы», но классификация охватывает также червей и троянов. Описания типов упрощены и не подходят для обнаружения реальных вредоносных программ.

## Состав и характеристика систем

| Компонент           | Логическая версия                                    | Продукционная версия                                           |
| ------------------- | ---------------------------------------------------- | -------------------------------------------------------------- |
| База знаний         | `cond/2`, `object/4` со списками нужных ответов      | `cond/2`, 12 отдельных правил `diagnose/1`                     |
| Механизм вывода     | `check_yes/1`, `check_no/1` обходят списки признаков | Условия `positive/1` и `negative/1` проверяются в телах правил |
| Интерфейс           | `consult/0`, вопросы 1/2, заключение                 | Тот же интерфейс                                               |
| Память консультации | Динамические `yes/1`, `no/1`                         | Динамические `yes/1`, `no/1`                                   |

Используются 10 признаков: заражение исполняемых файлов; поражение загрузочной области; использование макросов; распространение по сети; распространение по электронной почте; шифрование данных; похищение данных; сокрытие присутствия; изменение собственного кода; распространение через съёмные носители. В программах признаки пронумерованы от 1 до 10.

Система различает 12 типов: файловый вирус, полиморфный файловый вирус, скрытный файловый вирус, загрузочный вирус, загрузочный вирус на съёмном носителе, макровирус, почтовый макровирус, сетевой червь, почтовый червь, шифровальщик, шпионская программа и скрытный троян. У каждого типа своя комбинация признаков. Если признак не указан для типа, при распознавании требуется ответ «нет».

## Диаграммы потоков данных

В обеих версиях пользователь отвечает на вопросы интерфейса. Интерфейс сохраняет ответы, а механизм вывода сравнивает их с базой знаний и выбирает следующий вопрос или выдаёт заключение. После завершения консультации ответы удаляются.

`Пользователь → Интерфейс → Ответы → Механизм вывода ← База знаний`

`Механизм вывода → Вопрос или заключение → Интерфейс → Пользователь`

## Структурные диаграммы

- Логическая: `consult/0 → diagnose/1 → object/4 → check_yes/1 и check_no/1 → positive/1 и negative/1 → ask/1 → remember/2`.
- Продукционная: `consult/0 → diagnose/1 (12 альтернатив) → positive/1 и negative/1 → ask/1 → remember/2`.

## Тексты программ и механизм вывода

Полные тексты программ с комментариями находятся в [logic_expert.pl](logic_expert.pl) и [rule_expert.pl](rule_expert.pl). В логической версии объекты описаны фактами `object/4`. Общие рекурсивные предикаты проверяют списки положительных и отрицательных условий. В продукционной версии каждый тип описан отдельным правилом `diagnose/1`: если выполнены все условия правила, система выдаёт соответствующее заключение.

В обеих системах применяется обратный вывод: Prolog предполагает тип программы и проверяет его признаки. Если условия не выполнены, поиск с возвратом переходит к следующему типу. Сохранённый ответ используется повторно, поэтому один и тот же вопрос не задаётся дважды. Система принимает только ответы «да» и «нет».

## Запуск и машинные эксперименты

Нужен SWI-Prolog. Из каталога лабораторной работы:

```sh
swipl -q -s logic_expert.pl -g consult -t halt
swipl -q -s rule_expert.pl -g consult -t halt
```

На вопросы нужно отвечать `1` (да) или `2` (нет). Чтобы проверить все 12 типов и один набор признаков, отсутствующий в базе знаний, выполните:

```sh
swipl -q -s logic_expert.pl -g run_tests -t halt
swipl -q -s rule_expert.pl -g run_tests -t halt
```

Проверка считается успешной, если каждый из 12 типов распознан ровно один раз, а сочетание признаков «заражает исполняемые файлы» и «поражает загрузочную область» при остальных ответах «нет» не соответствует ни одному типу. Предикат `run_tests/0` выводит результат каждой проверки и завершается с ошибкой при расхождении. SWI-Prolog в этой среде не установлен, поэтому выполнение проверок пока не подтверждено.

## Вывод

Обе формы представления знаний решают одну задачу и используют общий протокол консультации. Логическую базу проще расширять фактами; продукционная запись делает условия каждого заключения явными. Полное совпадение по 10 признакам обеспечивает однозначный результат для заданных профилей, но ограничивает применение к новым и частично наблюдаемым случаям.
